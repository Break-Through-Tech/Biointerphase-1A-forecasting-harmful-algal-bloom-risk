# Conventions for this repo

Red-tide (*Karenia brevis*) forecasting for the Sarasota coast, Break Through Tech AI Studio, team Biointerphase 1A. Read this before changing code, notebooks or docs.

## Data

- Use only the project's own datasets in `data/`. No outside sources.
- Never delete or overwrite raw data. Cleaned tables are rebuilt by code, not edited by hand.

## Code

- **Names:** functions start with a verb (`make_folds`, `compute_scores`, `load_model_config`). Variables are descriptive; no unexplained abbreviations.
- **Every function has:**
  - type hints;
  - a Google-style docstring (`Args`, `Returns`, `Raises` if any, and an `Example` that runs as a doctest);
  - at least one unit test in `models/tests/`.
- **Comments** explain why, not what.
- **Models** follow the scikit-learn interface (`fit`, `predict`, `predict_proba`, `classes_`). Each model folder has a `train.py` with a `make_model()`-style function and calls `run_model`, so every model is scored on the same folds.
- **Settings** live in `models/model_config.toml`, not in code.
- **Requirements** are pinned to exact versions in `requirements.txt`.

## Evaluation

- **Validation:** split by August–July bloom year.
  - Forward-chaining is the main scheme: train only on earlier years.
  - Purge training weeks whose label falls in a test year.
  - Never use random splits.
- **Scores:** macro-F1 is the main score. Always report persistence alongside it, plus bloom onsets and escalations (quiet weeks that turn).
- **Comparisons:** a model only adds value if it beats persistence, or catches onsets persistence misses. Use the block bootstrap before calling a difference real.

## Results

- Commit `metrics.csv`, `metrics.json` and saved models (`final__*.joblib`). Don't commit charts or prediction files; they can be regenerated.
- Large files (`*.csv`, `*.json`, `*.joblib`) go through Git LFS.
- Commit settings, metrics and saved models together, so they always match.

## Git

- **Branches:** work on a feature branch (`<name>/<topic>`). Never push to `main`; merge through a pull request.
- **Commits:** one function or one model per commit, in an order a reader can follow. Every commit passes the tests.
- **Fixes:** a fix to an unmerged commit is folded into that commit (rebase), not added as a "fix" commit.
- **Commit message:**
  - Subject: imperative, under 72 characters ("Add onset scores").
  - Body:
    - what it adds and why;
    - an example or small diagram if it helps;
    - key results for models;
    - run time for models (wall-clock, per horizon);
    - sources with DOIs.

## Writing (docs, notebooks, commit messages)

- **Plain and concise:** no first person ("we", "our"), and no overly strong words ("proves", "always", "never" unless literally true).
- **Every claim** is cited with a source that was actually checked, or removed. If a threshold has no source, say "project choice".
- **Facts only:** state what the data show; don't speculate about causes.
- **Abbreviations:** define every one before using it.
- **Notebooks:**
  - Generated by `notebooks/build_*.py`: edit the builder, then rebuild.
  - Order: data first, then one section per experiment (question, method, result, bold one-line finding).
  - Every figure is followed by "What the figure shows".
  - A numbered source list at the end.
- **READMEs:** short. Setup, how to run, folder layout; no run times.

## Run the tests

From `models/`:

```bash
python -m pytest --doctest-modules common tests
```
